# 30. 실 데이터 객체 위치 추정 — 원본 ORB vs 우리 기술 ORB vs 우리 기술 ORB + 자이로 (RTX 5090 Laptop, 2026-10-18)

> 자이로(IMU) 데이터가 있는 실 데이터 녹화 4개(260901 cbnu)에서 세 구성을 비교했습니다. 인식은 노트북(RTX 5090 Laptop)에서, SLAM 은 Mac(192.168.219.106)에서 실시간으로 돌렸습니다. 세 구성은 원본 0.5 + ORB, 개선안 3 + 군집 먼저 + ORB, 개선안 3 + 군집 먼저 + ORB + 자이로 보정입니다. 우리 기술 두 구성은 녹화마다 3번씩 반복했습니다. 함께 Mac 에만 있던 수정 ORB-SLAM3 소스를 저장소로 가져왔습니다(4절). 실행 스크립트 · 채점 코드 · 결과는 `src/realdata/logs_gyro_261018/` 에 있습니다(`run_gyro_l5090.sh`, `score_gyro.py`, `results_gyro_l5090.json`).

## 0. 요약

- **최종 지도 맞음 / 잘못(녹화 4개, 기준 32개):**
  - 원본 0.5 + ORB: **19 / 15**
  - 개선안 3 + ORB: 3번 반복 모두 **31~32 / 1**
  - 개선안 3 + ORB + 자이로: 3번 반복 모두 **32 / 0**
- **우리 기술 vs 원본:**
  - 인식 빈도: 1.49 → 6.5 Hz (4.4배)
  - 기준까지 거리 중앙값: 5.7 → 2.4~2.7 cm
  - 10 cm 넘은 물체 비율: 43% → 5~6%
  - 27 문서의 다른 녹화 12개와 같은 결과입니다.
- **자이로 보정의 효과는 주로 SLAM 궤적에서 보입니다.** 녹화마다 가장 큰 루프 보정이 자이로 없이 중앙값 13.6 cm · 평균 18.9 cm · 최대 70.2 cm 에서, 자이로를 켜면 9.6 cm · 10.7 cm · 17.0 cm 로 줄었습니다. 같은 녹화를 반복했을 때 흔들림도 작아졌습니다(digut: 7.5 ~ 70.2 cm → 7.5 ~ 17.0 cm).
- **물체 결과의 차이는 작습니다.**
  - 잘못은 자이로 없이 12번 실행 중 3개, 자이로를 켜면 0개입니다.
  - 3개 중 2개는 장면에 없는 소스(Sauce_high)를 다른 물체 자리에 올린 인식 오류라 SLAM 과 직접 관계가 없습니다. 나머지 1개(longcircle 1회차 milk, 기준에서 22 cm)는 위치 오차입니다.
  - 기준까지 거리(중앙값 2.7 → 2.4 cm, 평균 3.4 → 3.4 cm)와 실행 중 점수 평균(71.7 → 71.8%)은 거의 같습니다.
- **SLAM 구분:** 이 문서의 "ORB" 는 원본 ORB-SLAM3 가 아니라 **Mac 의 수정 ORB-SLAM3 에서 자이로만 끈 것**입니다. 자이로와 상관없이 원본 버그 수정과 메모리 할당 개선이 들어 있습니다(4절). 2026-10-18 부터 Mac 실행은 자이로가 있는 녹화는 수정 ORB + 자이로, 없는 녹화는 수정 ORB 를 기본으로 합니다.

## 3. 해석

- **우리 기술은 원본보다 확실히 낫습니다.** 맞음 19 → 31~32, 잘못 15 → 0~1, 빈도 4.4배입니다. 반복 3번 모두 같은 결과라 우연이 아닙니다.
- **자이로 보정은 SLAM 궤적을 안정시킵니다.** 루프 보정의 평균이 절반 정도(18.9 → 10.7 cm)로 줄고, 자이로 없이 가끔 나오던 큰 보정(28.8 · 70.2 cm)이 사라졌습니다. 자이로는 회전을 직접 재므로 8자 경로의 회전 구간에서 생기는 방향 오차가 줄고, 잘못된 루프(회전이 자이로와 맞지 않는 장소 인식)도 거릅니다(4절).
- **물체 위치에서는 차이가 작습니다.** 루프 보정이 끝난 최종 지도에서는 자이로가 없어도 궤적이 대부분 바로잡히기 때문입니다. 위치 오차로 생긴 잘못은 자이로 없는 실행에서 1개(longcircle 1회 milk 22 cm)뿐입니다. 잘못 0개 대 3개 중 2개는 인식 오류(Sauce_high)라, 자이로가 물체 오류를 없앴다고 말하기는 어렵습니다.
- **정리:** 자이로 보정은 "물체 지도가 더 정확해진다" 보다 **"SLAM 이 덜 틀어지고 실행마다 덜 흔들린다"** 로 주장하는 것이 데이터에 맞습니다. 물체 결과는 같거나 조금 낫습니다.
