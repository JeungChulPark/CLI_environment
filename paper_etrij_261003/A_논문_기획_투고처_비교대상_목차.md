### 1. ETRI Journal에 맞는가

**결론: 맞다.** 본문 하나(시스템과 촬영 시각 키프레임 고정)로 정리하면 정규 논문(Regular Paper)으로 낼 수 있다. 비용이 없고 마감도 없어 일정 부담이 가장 적다.

**ETRI Journal에 내기 전에 고려할 점**

- 심사위원이 반드시 비전·로봇 전문가라는 보장이 없다. 그래서 도입부에서 "왜 두 장치로 나누는가, 그러면 무엇이 깨지는가(다섯 가지 문제)"를 그림 하나로 먼저 보여 주는 구성이 효과적이다. 초안의 그림 5가 그 역할을 한다.
- 노출도를 우선한다면 IROS 2027이나 RA-L에 먼저 내고, 인식부 실험과 LiDAR 실시예를 더한 확장판을 ETRI Journal에 내는 두 단계 방식도 가능하다.

### 3. 이 기술로 논문을 쓸 때의 강점과 보완점

#### 강점

1. **문제 정의가 분명하다.** "SLAM과 인식을 나누면 실시간성은 지켜지지만 시계, 좌표계, 연산 지연, 통신 지연, 사후 보정이라는 다섯 가지 불일치가 생긴다"는 틀이 있고, 구성 요소마다 대응하는 문제가 정해져 있다. 심사위원이 따라가기 쉬운 구조다.
2. **핵심 주장을 직접 증명하는 비교 실험이 있다.** 같은 인식 결과 8,964건을 등록 방식 (a)~(d)로 다시 계산했다. 시각(도착→촬영), 저장 좌표(지도→키프레임), 키프레임 선택(도착 시각→촬영 시각)의 효과가 하나씩 분리된다(9.67 → 3.08 → 1.59 → 1.51 cm, 보정이 끼어든 경우 30.8 → 5.4 → 1.5%). 시스템 논문에서 흔치 않게 깔끔한 증거다.
3. **실제 데이터의 규모가 크다.** 실시간 실행 기록 113회, 같은 설정 반복 40회, 공개 데이터셋 두 개(YCB-V, YCB-M), 실제 주행 네 종류가 있어 수치를 통계로 제시할 수 있다.
4. **범용성을 보여 준다.** 영상 SLAM(ORB-SLAM3)과 LiDAR SLAM(HDL-Graph-SLAM) 두 방식에 같은 방법을 적용했다. SLAM의 추정은 바꾸지 않고 키프레임 정보만 내보낸다.
5. **결과를 바꾸지 않는 SLAM 가속(24.7 → 15.4 ms, 정확도 동일)**과 메타데이터 시각 문제(연관 타임스탬프가 −2.1~+3.8초 어긋남) 같은 실무 발견이 있다. 재현하려는 연구자에게 도움이 되는 내용이다.
6. **한계를 수치로 밝힐 수 있다.** 가려진 물체(46% 대 3%)와 잘못된 루프 보정(40회 중 2회)을 숨기지 않고 적으면 심사에서 신뢰를 얻는다.

#### 심사에서 지적받기 쉬운 점과 대응

| 예상 지적 | 대응 |
|---|---|
| 각 요소(보간, 키프레임 상대 저장, 존재확률)는 이미 알려졌다. 새로운 점이 무엇인가 | 새로운 점을 "늦게 도착한 결과를 **촬영 시각의** 키프레임에 붙이는 것"으로 좁혀 말한다. (c)와 (d)의 차이(보정이 끼어든 130건)를 주 결과로 내세운다 |
| 실제 주행에 정답 자세가 없다 | 지금은 일관성 지표와 SLAM으로 만든 의사 정답을 쓴다. 저장소의 `apriltag_gt`로 물체 몇 개에 AprilTag 정답을 붙인 주행을 1~2회 추가하면 크게 보강된다 |
| YCB에서 찾은 비율이 원본보다 낮다(90.2 → 63.2%) | 논문의 주제를 인식기가 아니라 객체 지도로 두고, 인식기는 "틀린 답이 적고 빠른 것"이 목적이라고 밝힌다. GT 상자 조건(80.9%)으로 문구 검출의 영향을 분리해 보인다 |
| 녹화 재생이지 실제 로봇 실시간이 아니다 | 두 장치가 각자 센서 기록을 1배속으로 재생하며 실시간으로 처리했음을 정확히 쓴다. 가능하면 카트에서 바로 실행한 주행을 1회 추가한다 |
| 지연이 얼마일 때 효과가 있는가 | 기존 재생 도구(`objpose/pc/anchor_ablation.py`)로 인식 지연을 0~10초로 인위적으로 바꿔 (a)~(d)의 흩어짐을 그래프로 그린다. 새 주행 없이 할 수 있고 설득력이 크다 |
| 다른 객체 지도 시스템과 비교가 없다 | Fusion++ 같은 시스템은 실행 조건이 달라 직접 비교가 어렵다. 같은 추정기를 쓰는 기준선(지도 없이, tf2식 보간)과의 비교로 대신하고 관련 연구 표로 차이를 정리한다 |
| 실험마다 GPU가 다르다 | 한 장 비교는 RTX 5090(발표자료 기준), 실시간 실행은 이 PC(RTX 3080 Ti Laptop)로 보인다. 실험별 장치를 정확히 확인해 표로 적는다 |
| 코드·데이터 공개 여부 | 특허 출원 뒤 공개 범위를 정한다. 일부라도 공개하면 채택에 유리하다 |

#### 원고를 쓰는 방향

- **이야기는 하나로 정한다.** 이 초안은 "촬영 시각 키프레임 고정 + 이를 받쳐 주는 시스템"을 줄기로 삼았다. 인식부의 자세한 실험(물체별 표, 문구 선택)은 별도 논문(IPIU나 국내 학회지)으로 나누는 것이 분량과 집중도 면에서 낫다.
- **ETRI Journal 분량(8–10쪽)에 맞추려면** 4.1절 세부 수치, 표 4, 6.3절 일부를 줄이고 보충 자료로 옮긴다.
- **이름 규칙:** 주행은 조건 이름(어두운 실내 8자, 91초 실내, 밝은 실내 홀 8자, 큰 8자)으로 부르고, 장소와 기관 이름은 쓰지 않는다. 실외 주행은 없다.

**원고에 반영할 점**

- **재실행 차이:** 우리가 다시 돌린 SAM-6D(78.7)는 논문 값(83.4)보다 4.7 낮다. 원인(평가 프레임 수, 버전, 설정)을 확인해 원고에 적어야 한다. 그대로 두면 심사위원이 비교 전체를 의심할 수 있다.
- **우리 방법의 위치:** 정확도 순위로는 경쟁이 되지 않는다. 대신 "1초 이하에서 틀린 답이 가장 적은 방법"으로 위치를 잡는 것이 맞다. 리더보드 상위권은 장당 7~35초가 걸린다. 표에 처리 시간과 틀린 답 비율을 함께 두면 이 점이 드러난다.
- **처리 시간 비교:** 장당 시간은 GPU가 서로 달라 그대로 비교할 수 없다. 같은 GPU에서 SAM-6D, Co-op 거친 단계, GigaPose를 다시 재야 한다 (계획서 E4).

### 2. 특허 작성 시 비교할 논문·특허

발표자료 61쪽의 목록에 이번 조사 결과를 더했다. **새로 확인된 항목에 표시**를 했다.

| 대상 | 겹치는 부분 | 본 발명과 다른 점 (사실 기준) |
|---|---|---|
| SAM-6D (CVPR24) | 제로샷 6D 추정 전체 구조 (ISM, PEM) | 화면 전체 분할, 점수 가중 합과 1등 출력, '없음' 출력 없음, 지도 없음 |
| CNOS, FoundPose, GigaPose, FreeZeV2 | 템플릿 기반 제로샷 인식 | 한 장 단위 카메라 기준 결과, 순차 관문·색 관문·배타 배정 없음 |
| **CLON (arXiv 2609.04784, 2026-09-04)** 새로 확인 | **색 서술을 넣은 텍스트 프롬프트로 후보 수를 67.3개에서 13.6개로 줄임** → 본 발명의 텍스트 프롬프트 후보 생성과 가장 가깝다 | 순차 관문, 색조·채도 분포 관문, '없음' 출력은 기술되지 않음. **출원 전에 공개된 자료이므로 선행기술로 다루어야 한다** |
| NIDS-Net, MUSE, Grounded-SAM | 문구 검출 후 템플릿 비교 | 순차 관문·색 분포 관문·배타 판정 없음 |
| SLAM++, CubeSLAM, QuadricSLAM, VOOM | 객체를 지도에 둠 | 객체로 카메라 위치를 보정, 물체별 검출기·형상 필요, 지연 처리 없음 |
| Fusion++ | 존재확률(Beta 분포), 기댓값 0.1 미만 삭제 | 미검출 판정이 거리 조건이 아닌 투영 크기(50² 픽셀) 기준. 중복 처리는 향후 과제로 남김. 한 시스템 4–8 Hz |
| POCD, Khronos, Hydra | 변화하는 객체 지도, 베이즈 갱신 | 제로샷 CAD 6D 아님, 촬영 시각 키프레임 고정 없음 |
| Merrill 외 (CVPR22) | 대칭 고려 객체 SLAM, YCB-V 6D | 카이제곱 이상치 게이트만 사용, 물체별 키포인트 학습 |
| **DSP-SLAM++ (arXiv 2606.25953, 2026-06-24)** 새로 확인 | **비동기 객체 처리: 작업을 넣을 때 그 시점 자세를 묶고, 작업 큐와 결과 큐를 둠** | 한 장치, 키프레임 목록 재전송 없음, 실외. **출원 전 공개 자료이므로 촬영 시각 고정 부분과 꼼꼼히 비교해야 한다** |
| MaskFusion (ISMAR18) | 인식 비동기 실행 | 한 장치·한 카메라, 프레임 큐로 SLAM 자체를 늦춤, 루프 보정 반영 없음 |
| Liu 외 (MobiCom19) | 두 장치(단말·엣지), 늦은 결과의 화면 보정 | 2D 박스, 지도·키프레임 없음 |
| Zorina 외 (RA-L 2025) | 인식(5 Hz)과 출력(1 kHz) 주기 분리 | 지도 없음, 한 물체 자세 궤적 |
| Lost & Found (RA-L25) | 객체 추적, 1.15 s 지연 명시 | 지연을 보상하지 않음, 지도 없음 |
| Magic Leap US 11,206,507 B2 | 원점→키프레임→장치 변환을 연결 | 사용자가 놓은 가상 객체 대상, 인식 결과의 촬영 시각 선택 없음 |
| **Rivian US 12,313,726 B2** 새로 확인 | 늦게 도착한 측정을 시간순으로 넣고 상태를 다시 전파 | 차량 상태 추정. 객체를 키프레임에 고정하지 않음. 변리사 확인 필요 |
| ROS tf2 | 시각 지정 변환 조회, 변환이 올 때까지 대기 | 저장한 결과를 지도 보정 뒤에 다시 계산하지 않음 |

**특허 쪽에서 할 일**

1. **CLON과 DSP-SLAM++를 변리사에게 추가로 전달한다.** 둘 다 2026년에 공개되어 출원보다 앞선다.
   - CLON: 텍스트 프롬프트 후보 생성과 겹친다.
   - DSP-SLAM++: 비동기 객체 처리와 시점 자세 묶기가 겹친다.
2. **차이를 명세서에 분명히 적는다.** 본 발명이 두 문헌과 다른 점은 다음과 같다.
   - 촬영 시각의 기준 키프레임과 함께 키프레임 목록을 다시 보낸다.
   - 다른 장치에서 SLAM 자세가 늦게 올 때 기다렸다가 등록한다.
   - 색조·채도 분포 관문과 '없음' 출력을 갖춘 순차 관문을 쓴다.
3. **Rivian 특허는 변리사가 관련성을 판단한다.** 늦게 온 측정을 시간순으로 다시 넣는 일반 기술이다.
