## 14. 기술 상세 — 원본 SAM-6D 와 우리 개선안, 단계별로 (2026-10-07)

> 이 문서는 실험 수치가 아니라 **방법 자체**를 설명합니다. 원본 SAM-6D 가 각 단계에서 무엇을 어떻게 하는지, 우리 기술(배포)과 개선안이 그 자리에서 무엇을 바꿨는지, 왜 바꿨는지, 그 결과 무엇이 좋아지고 무엇을 잃는지를 코드 기준으로 적었습니다. 기준값과 수식은 `sam6d_realtime/yolo_ism.py`, `yolo_ism_object_n.py`, `realtime/sam6d_core.py`, `realtime/verify_config.py`, PEM `utils/model_utils.py`, 원본 `Instance_Segmentation_Model/model/detector.py` 에서 확인한 값입니다. 수치 근거는 07(한 장 평가)·08·13(실시간)·12(ViT-L) 문서를 가리킵니다.

### 0. 한눈에 보기

| 단계 | 원본 SAM-6D | 우리 기술 (배포, L4) | 개선안 1 (배포에서 바꾼 것만) |
|---|---|---|---|
| ① 후보 영역 | FastSAM-x 가 화면 전체를 분할. 장당 약 41개 마스크 | YOLO-World 에 물체별 **문구**를 주어 상자를 받고, MobileSAM 으로 상자 안만 분할. 장당 약 7개 | 문구를 검증 프레임에서 고른 **새 문구 ①** 로 교체 (YCB 21개 중 12개) |
| ② 특징 | DINOv2 **ViT-L**/14. CLS(의미) + 패치(외형) | DINOv2 **ViT-S**/14. 같은 전처리, 외형은 중간 블록 [2, 9] | 같음 |
| ③ 물체 판정 | 의미·외형·기하 점수를 **합산**해 물체마다 1위 마스크를 고르고 기준(기본 0.2, 비교 실험 0.5)을 넘으면 답 | 의미·외형·색상 **관문 세 개를 모두** 넘어야 답. 상자는 의미 1위 물체에게만(**독점 배정**), 1위가 떨어지면 상자 폐기 | 관문 기준값 완화(의미 0.35→0.25, 색상 0.12→0.06) + **배정 대안**(1위가 떨어지면 2·3위에게 상자를 넘김) |
| ④ 자세 추정 | PEM. 자세 가설 6000 → 300개, 기하 점수 **1위를 답**으로 | 같은 PEM, 같은 가중치. 관문 통과 물체만 넣음 | 같음 |
| ⑤ 자세 검증 | 없음 | 300개 가설을 **윤곽 → 무늬 → 합의**로 걸러 채택 또는 "답 없음" | 같음 (선택: 검증 후보 50개로 경량화) |
| 지도 | 매 프레임 결과를 그대로 올림 | 검증 통과 자세만 올림, 같은 물체 사본 억제 | 같음 |

**설계 사상의 차이 한 줄:** 원본은 "후보를 넓게 뿌리고 점수 합산으로 가장 그럴듯한 것을 고른다(항상 답한다)", 우리는 "찾을 물체를 문구로 좁히고, 확실하지 않으면 답하지 않는다". 그래서 원본은 **찾는 수**(YCB-V 900장 92.9%)에서, 우리는 **오답 억제**(오답/장 0.287 → 0.028, 정답 비율 93.7 → 99.0%)에서 앞섭니다(07 §2.1).

### 0-1. "개선안"이 여러 개다 — 번호별 정의

문서(07·08·13)에서 "개선안"은 번호가 붙은 네 개와 이름이 붙은 변형 둘을 가리킵니다. 모두 **우리 기술 배포(L4)** 를 기준으로 한 곳을 바꾼 것입니다. 본문에서 "개선안"이라고만 쓰면 개선안 1 입니다.

| 이름 | 후보 영역 | 특징 | 물체 판정 | 자세 | 한 줄 요약 | 결과 태그 |
|---|---|---|---|---|---|---|
| 우리 기술 (배포, L4) | 문구 상자 + MobileSAM | ViT-S | 배포 관문(0.35 / 0.605 / 0.12) + 독점 배정 | PEM + 검증 켬 | 기준점 | ours / v2 |
| **개선안 1** ("개선안") | 같음 (YCB 는 새 문구 ①) | ViT-S | **완화 관문**(0.25 / 0.605 / 0.06) + **배정 대안** | PEM + 검증 켬 | 판정만 느슨하게 해 재현율 회복 | g13 / g13p |
| **개선안 2** | **FastSAM-x 전체 분할** | ViT-S | **원본 판정 0.5** | PEM(원본 코드), 검증 **없음** | 원본에서 ViT-L → ViT-S 만 | origS05 / origS_th05 |

| 개선안 4 | FastSAM-x 전체 분할 | ViT-S | 원본 판정 0.5 | PEM(우리 코드), 검증 끔 | 개선안 3 의 검증 끔 짝 (결과는 2 와 같음) | hybS05_nover |
| A안 | FastSAM-x 상자 → MobileSAM 마스크 | ViT-S | 배포 관문 + 독점 배정 | PEM + 검증 켬 | 원본 후보에 우리 판정 | gateA |

**뜻과 대표 결과**
1. **개선안 1** — 문구 상자와 관문 구조는 그대로, 관문 기준값을 낮추고 1위가 떨어진 상자를 2·3위에게 넘기는 배정 대안을 켬. 목적은 배포의 낮은 재현율(61%) 회복. 36장 58.2 → 76.4%, 실제 영상 5개 39/40(오답 4: 식혜→소스 3), 260901(4090) 8/0.
2. **개선안 2** — 원본 SAM-6D 그대로에 특징만 ViT-S. 속도 실험용. 검증이 없어 오답이 많아(260901 최종 지도 오답 4) 단독 구성은 아님.
3. **개선안 3** — 개선안 2 + 우리 자세 검증. 문구가 필요 없어 처음 보는 물체도 다루며, 실제 데이터 5개 모두 오답 0·YCB 실시간 54/55 로 두 데이터 균형이 가장 좋았음(08 §7). 260901(4090) 7/1, 평균 점수 1위.
4. **개선안 4** — 개선안 3 에서 검증만 끔. 같은 코드 경로에서 검증 효과를 재기 위한 짝.
5. **A안** — FastSAM 후보 + 우리 관문. 실제 데이터 40/40·오답 0 으로 가장 정확하지만 0.7~1.7 Hz 로 느리고 YCB 39/55.
6. **개선안 1 + 후보 50개** — 자세 검증 후보를 줄인 경량화. 36장 −28% 시간·정확도 유지, 실시간 YCB 1.5배, 실제 데이터 영상 끝 오답 증가.

**논문용 해석:** 개선안 1 과 3 이 서로 다른 방향의 두 후보입니다. 1 은 "정해진 물체를 문구로 빠르게, 오답 적게"(실제 환경), 3 은 "처음 보는 물체까지 넓게 보되 검증으로 오답을 막기"(일반성). 둘 다 자세 검증을 공통으로 쓰므로 10절의 "인식은 제안하고 검증이 결정한다"가 둘을 한 틀로 묶습니다. 셋(원본·개선안 1·개선안 3)을 직접 비교한 자료는 08 §4·§6·§7, 07 §3.7~3.9, 13 문서, 그리고 2026-10-07 4090 재실행(15 문서 예정)에 있습니다.

### 1. 공통 전제

- **입력:** RGB 영상, 정렬된 깊이 영상(mm), 카메라 내부 파라미터 K, 찾을 물체의 CAD 모델(PLY).
- **템플릿:** 물체마다 CAD 를 42개 시점에서 렌더한 RGB·마스크·3D 좌표 영상(BlenderProc, 원본 SAM-6D 의 `render_templates` 와 같은 시점 집합). 두 방식 모두 이 42장에서 DINOv2 특징을 미리 뽑아 둡니다(우리는 `features/<물체>_cls.pt`, `_appe.pt`, `_appe_b2-9.pt`, 색상 히스토그램 `_hsv.npz` 로 캐시).
- **같은 것:** PEM 모델과 가중치(`sam-6d-pem-base.pth`), 템플릿, CAD, 평가 방식. 두 방식의 차이는 전부 ①②③⑤에 있습니다.

### 2. 단계 ① 후보 영역 (어디에 물체가 있을 수 있나)

#### 원본: FastSAM-x 전체 분할
- FastSAM-x(YOLOv8 기반 "모든 것 분할")를 640 해상도로 돌려 화면의 모든 덩어리를 마스크로 냅니다. 설정은 원본 그대로: 신뢰도 0.25, 마스크 겹침 0.9, 최대 200개.
- 후처리로 화면 변의 5% 미만인 상자와 화면의 3e-4 미만인 마스크를 버립니다. 이렇게 남는 것이 **장당 평균 41개**(YCB-V 900장).
- 성격: 무엇을 찾을지 모르고 분할합니다. 배경·선반·물체 일부·중복 마스크가 섞여 있지만, 정답 물체를 IoU 0.5 이상으로 덮는 마스크가 후보 안에 있는 비율이 **97.6%** 로 매우 높습니다(07 §3.11). 처음 보는 물체도 후보에 들어갑니다.
- 비용: 분할 자체는 33 ms 로 싸지만, 뒤 단계의 특징 계산이 후보 수에 비례해 비쌉니다(ViT-L 로 41개 = 857 ms).

#### 우리: YOLO-World 문구 상자 + MobileSAM
- **문구 상자:** YOLO-World(m) 는 글로 된 문구("blue coffee can")를 받아 그 뜻에 맞는 상자를 찾는 열린 어휘 검출기입니다. 물체마다 문구 하나를 등록하고(실제 데이터 9종, YCB 21종), 한 프레임에서 모든 문구를 동시에 질의합니다(multi-label). 물체마다 점수 상위 3개, 점수 0.02 이상만 남깁니다. 결과 **장당 평균 7개**.
- **MobileSAM:** 상자마다 MobileSAM 에 상자를 프롬프트로 주어 마스크를 만듭니다. FastSAM 처럼 화면 전체를 분할하지 않고 상자 안만 분할하므로 68 ms 입니다.
- 성격: 찾을 물체가 정해져 있다는 사실을 처음부터 씁니다. 후보 자체에 이미 "어느 물체인가"라는 이름(문구)이 붙어 있어 상자 독점 배정이 가능하고, 배경·다른 물체를 집어 올 기회가 적습니다(같은 판정 0.5 위에서 오답 0.201 → 0.168/장).
- **속도에 대한 주의:** 인식 단계만 보면 빠르지만(특징 857 → 22 ms), 전체 파이프라인에서는 그 시간을 ⑤ 자세 검증이 거의 다 다시 쓰므로 원본과 비슷합니다(900장 한 장 4090: 원본 530 대 우리 514 ms). 문구 상자의 이득은 속도가 아니라 **오답 억제와 "검증에 쓸 시간을 확보한 것"**으로 읽어야 합니다. 대신 문구가 안 잡히는 물체(집게·가위·푸딩 상자)는 후보가 0개여서 답할 수 없습니다(IoU 0.5 커버 91.3%).
- **문구 선택:** 배포 문구는 손으로 정한 것(검출 재현율 71%)이고, 개선안의 새 문구 ① 은 검증 프레임 188장에서 후보 문구들의 재현율을 재어 1점 넘게 좋을 때만 교체한 것입니다(84%). "red cracker box → red box", "power drill → cordless drill" 처럼 상품명보다 색·형태 단어로 바뀌었습니다. 새 문구만 바꾸면 찾은 비율 61.4 → 66.3%, 오답은 그대로입니다(07 §2.1 L5).

### 3. 단계 ② 특징 (후보가 어떤 물체를 닮았나)

두 방식 모두 후보 마스크의 상자를 정사각형으로 잘라 224×224 로 맞춘 뒤(SAM-6D 의 CropResizePad 와 동일) DINOv2 에 넣어 두 종류 특징을 뽑습니다.
- **CLS 토큰:** 잘린 영역 전체를 요약한 벡터. "의미" 점수에 씁니다.
- **패치 토큰:** 14×14 픽셀 격자 하나하나의 벡터(16×16 = 256개). 마스크 안쪽 패치만 골라 "외형" 점수에 씁니다.

| | 원본 | 우리 |
|---|---|---|
| 모델 | ViT-L/14 (24층, 1024차원, 300M 파라미터) | ViT-S/14 (12층, 384차원, 22M) |
| 외형 특징 층 | 마지막 층 | 중간 블록 **2, 9** 의 평균 (마지막 층 11 은 의미에 치우쳐 외형 구별력이 낮아 2026-07 에 교체) |
| 시간 (900장, 노트북) | 41개 후보 857 ms | 7개 후보 22 ms |
| 효과 | 후보 41개 사이에서 좋은 마스크를 가려내는 힘이 큼 (ViT-S 로 바꾸면 −2.3%p) | 문구로 좁힌 7개에서는 ViT-L 과 차이 없음 (12 문서: 82.8 ↔ 82.7%) |

우리 관문의 기준값은 ViT-S 점수 분포에 맞춰 고른 것이어서, 특징 모델만 ViT-L 로 바꾸면 같은 기준값이 훨씬 엄격해져 찾은 비율이 72 → 44% 로 떨어집니다(12 문서). ViT-L 을 쓰려면 기준값을 다시 골라야 합니다.

### 4. 단계 ③ 물체 판정 (이 후보가 그 물체인가) — 가장 크게 다른 곳

#### 4.1 원본: 점수 합산 → 물체별 1위 → 기준값

후보 하나하나에 대해 모든 물체와의 점수를 계산합니다.
1. **의미 점수 s_sem:** 후보 CLS 와 그 물체 템플릿 42장 CLS 의 코사인 유사도 가운데 상위 5개 평균(`avg_5`). 후보마다 가장 높은 물체를 그 후보의 "이름"으로 정하고, 0.2 미만이면 후보를 버립니다.
2. **외형 점수 s_appe:** 의미 점수가 가장 높았던 템플릿 하나와 패치 단위로 비교합니다. 후보 마스크 안의 패치마다 템플릿 패치 중 가장 닮은 것의 코사인을 찾아 평균합니다.
3. **기하 점수 s_geo 와 가시도 v:** 그 템플릿의 시점(회전)과 깊이에서 추정한 이동으로 CAD 를 화면에 투영해 후보 마스크와의 IoU 를 s_geo 로, 템플릿 패치 중 후보에서 보이는 비율을 가시도 v 로 둡니다.
4. **최종 점수** = (s_sem + s_appe + s_geo × v) / (2 + v). 같은 물체 이름의 후보끼리 겹침 0.25 로 NMS 하고, **물체마다 최종 점수 1위 후보 하나**를 답으로 냅니다. 원본 기본값은 1위면 그대로 답(점수 기준 0.2 는 1 단계에서 이미 적용). 우리 비교 실험의 "원본 0.5" 는 이 최종 점수가 0.5 를 넘어야 답하도록 한 것입니다.

**성격과 약점**
- 세 점수를 더하므로 하나가 낮아도 다른 둘이 높으면 통과합니다. 모양이 같고 색만 다른 물체(식혜 ↔ 소스, 곰 인형 ↔ 공룡 인형)는 의미·외형이 비슷해 이름이 뒤바뀔 수 있고, 뒤바뀌어도 점수가 높아 답으로 나갑니다.
- 물체마다 "1위"는 항상 존재합니다. 장면에 그 물체가 없어도 가장 닮은 배경 덩어리가 0.2(또는 0.5)만 넘으면 답이 됩니다. YCB-V 실시간에서 장면에 없는 물체가 26개 올라간 원인입니다(13 문서 2절).
- 기준값을 올리면(0.2 → 0.5) 오답은 0.282 → 0.182/장으로 줄지만 찾은 비율도 93.3 → 87.6% 로 줍니다(07 §3.11).

#### 4.2 우리: 관문 세 개 + 상자 독점 배정

우리는 점수를 더하지 않습니다. **각각이 독립된 관문**이고 셋을 모두 넘어야 합니다. 그리고 상자(후보)마다 주인을 한 물체로 정합니다.

**관문**

| 관문 | 계산 | 배포 기준 | 개선안 기준 | 막으려는 것 |
|---|---|---|---|---|
| 의미 | CLS 코사인, 템플릿 상위 5개 평균 (원본 s_sem 과 같음) | ≥ 0.35 | ≥ 0.25 | 그 물체 종류가 아닌 것 |
| 외형 | 마스크 안 패치마다 템플릿 패치 최대 코사인, 평균. 블록 2·9 평균 | ≥ 0.605 | ≥ 0.605 | 종류는 같아도 겉모습(무늬·형태)이 다른 것 |
| 색상 | 마스크 안 HSV 2차원 히스토그램(색상 16 × 채도 8 = 128칸, L1 정규화)과 템플릿 42장 히스토그램의 Bhattacharyya 유사도 최대값 | ≥ 0.12 | ≥ 0.06 | 모양은 같고 색이 다른 쌍 (DINOv2 가 못 가름) |

- 템플릿 색상 히스토그램은 렌더 영상에서 만들 때 색상을 −6° 돌리고 채도를 1.3배 해 실제 카메라 색감에 맞춘 것입니다(물체별 보정값은 0).
- 기하 점수는 쓰지 않습니다. 깊이로 자세를 미리 추정해 투영하는 비용(원본 판정 28 ms 의 대부분)을 없애고, 그 역할은 ⑤ 자세 검증이 더 정확하게 맡습니다.
- 기준값은 검증 프레임 188장에서 격자 탐색으로 골랐습니다(07 §2.6). 배포값은 정밀도 92.3%/찾음 61.7%, 개선안 완화값은 91.3%/68.2% 지점입니다. 외형 기준을 0.55 로 내리면 정밀도가 84% 로 급락해 두 설정 모두 0.605 를 유지합니다.

**상자 독점 배정 (배포)** — 한 상자에 여러 물체 이름이 붙을 수 있을 때 주인을 정하는 규칙입니다.

1. 상자마다 등록된 모든 물체와의 의미 점수를 구합니다.
2. 의미 점수 **1위 물체**를 그 상자의 유일한 주인 후보로 삼습니다. 단, 1위와 템플릿 유사도 0.6 이상인 "닮은 물체"가 있으면(식혜·소스·머그컵처럼) 그 무리 안에서는 **색상 점수**가 높은 물체를 1위로 바꿉니다(색상 동률 판정).
3. 그 1위 물체에 대해서만 세 관문을 검사합니다. 하나라도 떨어지면 **상자를 버립니다.** 2위 물체에게 넘기지 않습니다.
4. 한 물체가 상자 여러 개를 통과하면 외형 점수가 가장 높은 하나만 남깁니다(물체당 답 하나).
5. 서로 다른 물체의 답이 0.9 이상 겹치면(교차 물체 NMS) 외형 순위 점수가 높은 쪽만 남깁니다.

왜 독점인가: 같은 상자가 두 물체 이름으로 올라가는 "중복"과, 1위가 아닌 물체에게 상자를 넘겨 생기는 "이름 혼동"을 구조적으로 막기 위해서입니다. 대가는 1위 물체가 관문에서 떨어지면 그 상자에 실제로 있던 2위 물체도 찾지 못한다는 점입니다. YCB-V 900장에서 **푸딩 상자 0%**, 나무 블록 13% 가 이 때문입니다(12 문서 2절). 36장 기준 손실은 약 −18%p 로, 문구 상자(−15%p)와 함께 찾은 비율 손실의 두 축입니다(06 문서).

**배정 대안 (개선안)** — 위 3단계의 "버린다"를 바꾼 것입니다.

1. 의미 관문을 넘는 모든 (상자, 물체) 쌍을 후보로 모읍니다. 상자의 원래 1위(색상 동률 판정 뒤)에게는 우선권 가산점 +1 을 줍니다.
2. 후보 쌍을 의미 점수 순으로 꺼내며 **탐욕 배정**합니다. 꺼낸 쌍이 외형·색상 관문을 넘으면 그 상자와 물체를 둘 다 "사용됨"으로 표시합니다. 상자도 물체도 한 번씩만 쓰입니다.
3. 상자의 1위 물체가 관문에서 떨어졌거나 이미 다른 상자를 차지했으면, 같은 상자가 2위·3위 물체의 차례에 다시 검사됩니다.

효과: 버려지던 상자가 살아나 찾은 비율이 오릅니다(900장 인식 72.3 → 80.6%, 36장 관문 탈락 35.8 → 26.7%). 대가: 2·3위에게 넘긴 상자에 다른 이름이 붙는 경우가 늘어 인식 단계 오답이 0.264 → 0.433/장이 되고, 자세 검증 뒤에도 일부 남습니다(36장 0.028 → 0.083; 실제 데이터 4개에서 식혜 → 소스 3건). 그래서 배정 대안은 **자세 검증과 함께 써야** 하고, 오답이 전혀 없어야 하는 현장이면 끄는 쪽이 안전합니다.

### 5. 단계 ④ 자세 추정 (PEM) — 둘이 같음

- **입력:** 판정이 넘겨준 마스크, 그 안의 깊이로 만든 3D 점 2,048개, 잘린 RGB(ViT-Base 특징), CAD 모델 점 2,048개, 템플릿 점 5,000개.
- **거친 정합:** 관측 점 196개와 모델 점을 학습된 특징으로 짝지어 자세 가설 **6,000개**를 만들고, 점 일치 점수 상위 **300개**를 남깁니다.
- **정밀 정합:** 300개 가설 각각을 2,048개 점으로 다듬고, 가설마다 "관측 점과 모델 점이 얼마나 겹치는가"의 **기하 점수**를 냅니다. 깊이(3D 모양)만 보고 색은 보지 않습니다.
- **원본의 출력:** 기하 점수 1위 가설 하나. 점수가 낮아도 1위는 있으므로 판정이 넘긴 물체는 반드시 자세가 나옵니다.
- **우리의 출력:** 300개 가설과 점수를 그대로 ⑤ 로 넘깁니다. 모델·가중치·가설 생성은 원본과 동일하고, 넣는 물체 수만 관문 때문에 적어 시간이 줍니다(노트북 662 → 224 ms/장).

기하 점수 1위를 믿을 수 없는 경우: 대칭 물체(캔·병·상자)는 돌아간 자세도 점수가 같거나 높아 라벨 방향이 틀릴 수 있고, 판정이 잘못 고른 물체(공룡 자리의 곰)에도 억지로 맞춘 자세가 1위가 됩니다. 배경 덩어리에도 1위는 있습니다. 원본의 실시간 오답(13 문서)이 대부분 여기서 지도에 올라갑니다.

### 6. 단계 ⑤ 자세 검증 — 우리만 있음

300개 가설을 세 번 거르고, 남은 것이 없으면 그 물체를 **답하지 않습니다.** 자세를 고치는 것이 아니라 틀린 자세를 버리는 단계라 "보정"보다 "검증"이 정확한 이름입니다.

1. **유효성:** 회전 행렬이 정규직교(det > 0.99)이고 투영이 화면 안에 들어오는 가설만 남깁니다.
2. **윤곽 (mask_iou ≥ 0.421):** 가설 자세로 CAD 점을 카메라에 투영해 실루엣 마스크를 그립니다(점 반지름 2 px, 닫힘 1 px, 점 밀도에 따라 반지름 자동 조정). 관측 마스크와의 IoU 가 기준 미만이면 탈락. 엉뚱한 위치·크기의 가설을 걸러 냅니다.
3. **무늬 (texture ≥ 0.450):** 가설 자세로 렌더한 모습과 실제 영상의 질감을 비교한 점수. 모양은 맞지만 뒤집히거나 돌아간 가설(라벨이 뒤로 간 캔, 거꾸로 선 상자)을 걸러 냅니다. 기하 점수가 못 보는 **색 영상 정보**를 여기서 처음 씁니다.
4. **합의 (occupancy ≥ 0.5, YCB 0.3):** 2·3 을 통과한 생존 가설들끼리 회전 20°·이동 25 mm 안에 모이는 무리를 찾습니다. 가장 큰 무리(동점이면 기하 순위가 좋은 중심)가 생존 가설의 50% 이상이면 그 중심 가설을 답으로 채택하고, 흩어져 있으면 "수렴 부족"으로 답하지 않습니다. 생존 가설이 하나뿐이면 그대로 채택합니다. 대칭 물체(식혜·소스는 z축, 머그컵은 기울어진 축)는 대칭축 둘레 10° 간격으로 돈 자세를 같은 자세로 칩니다.

탈락 사유는 `candidate_projection_invalid`, `mask_filter_empty`, `texture_filter_empty`, `convergence_insufficient` 네 가지로 기록되어 뒤에 분석할 수 있습니다.

**효과:** 900장에서 오답 0.114 → 0.028/장(L3 → L4), 찾은 비율 −2~3%p. 36장에서는 모든 구성의 인식 통과 후보 가운데 7~12% 를 걸러 내고 그 안에 틀린 답이 거의 다 들어 있습니다. 실시간에서 검증을 끄면 잘못 올라간 물체가 YCB 3장면 5 → 42, 260901 0 → 4 로 늘어, 검증은 "찾는 수"가 아니라 "오답"을 책임지는 단계입니다(10 문서).
**비용:** 300개를 다시 그려 비교하므로 노트북 약 935 ms, 4090 약 290 ms. 우리 기술 전체 시간의 대부분입니다. 검증 후보를 기하 상위 50개로 줄이면 36장에서 −28% 시간에 정확도가 유지되지만, 실시간 영상 끝 오답이 늘어 기본값으로 쓰기는 이릅니다(07 §3.4). 반정밀도(fp16/bf16)는 정확도가 급락해 쓸 수 없습니다.

### 7. 지도 단계 (실시간)

허브는 매 프레임의 (물체, 자세)를 SLAM 좌표계로 옮겨 지도에 올립니다. 원본은 자세 검증이 없어 매 프레임 1위 자세가 그대로 올라가고, 틀린 자세가 먼저 올라가면 맞는 자세가 들어올 자리를 막습니다(10 문서 2-1절 검증 끔 사례). 우리는 검증을 통과한 자세만 올리고 같은 물체의 사본을 억제합니다. 실제 영상의 채점은 기준 위치 20 cm 이내, YCB-V 는 정답 자세(ADD-S < 지름 10%)로 합니다.

### 10. 논문 논리 구성 — 인식 단계에서 원본보다 좋은 점과 주장의 세우기 (2026-10-07 추가)

#### 10.1 인식 단계에서 원본보다 실제로 좋은 것 (데이터가 있는 것)

| 좋은 점 | 왜 원본은 못 하나 | 근거 |
|---|---|---|
| **답하지 않을 수 있다** | 원본은 물체마다 1위 후보가 항상 있어 장면에 없는 물체도 올림 | YCB-V 실시간 "장면에 없는 물체" 26 → 11 (13 문서), 정답 비율 93.7 → 99.0% (07 §2.1) |
| **중복·이름 혼동이 구조적으로 안 생긴다** | 원본은 같은 영역을 두 물체로, 같은 물체를 두 번 답할 수 있음 | 실시간 "같은 물체 중복" 3 → 0; 실제 영상의 공룡↔곰, 식혜→소스 혼동은 원본에서 반복 (08 §7) |
| **색상 관문으로 닮은 물체를 가른다** | 원본 점수(의미·외형·기하)에 색 정보가 없고 DINOv2 는 색만 다른 쌍을 못 가름 | 실제 영상 이름 혼동 사례, 색상 동률 판정 설계 근거 (4.2절) |
| **후보에 이름이 붙어 와 상자 주인을 정할 수 있다** | FastSAM 마스크는 이름이 없어 모든 물체와 비교 | 독점 배정·배정 대안이 이 구조 위에서만 가능 |
| **원본과 같은 시간 안에 검증을 넣을 자리를 만든다** | 원본은 ViT-L 특징 계산에 시간을 다 씀 | 900장 한 장 4090: 530 대 514 ms (06 문서) |

#### 10.2 솔직히 약한 것 (피하거나 미리 인정할 것)

- **같은 앞단 위에서 "인식까지만" 비교하면 원본 판정 0.5 가 더 좋습니다.** 문구 상자 + ViT-L + 원본 0.5 가 82.7% / 오답 0.167 인데 우리 관문(완화)은 72.3% / 0.264 입니다(12 문서 2절). 관문의 가치는 인식 단계 단독이 아니라 **자세 검증과 묶였을 때**, 그리고 **닮은 물체가 있는 실제 장면**에서 나옵니다.
- **찾는 수는 원본이 많습니다** (92.9 대 61.4%, 개선안 36장 76.4%). 숨길 수 없으니 "선택"으로 써야 합니다.
- **배정 대안**은 인식 오답을 1.6배 늘리고 검증 뒤에도 일부 남깁니다(실제 데이터 식혜→소스 3건). 핵심 기여로 세우기엔 약하고 "재현율 회복 옵션"으로 두는 것이 안전합니다.
- **속도는 이득이 아닙니다.** 전체 파이프라인은 원본과 같은 수준(3절·2절 주의). "빠르다"고 쓰지 않습니다.

#### 10.3 권하는 주장: "인식은 제안하고, 검증이 결정한다"

주장을 **"더 잘 인식한다"가 아니라 "지도에 틀린 물체를 남기지 않으면서 쓸 만한 재현율과 같은 속도를 유지한다"** 로 세우면 데이터와 정확히 맞고, 인식 단계의 모든 설계가 한 줄로 설명됩니다.

- **문제 정의.** 로봇 물체 지도에서는 못 찾은 물체(다음 프레임에 다시 기회)보다 틀린 물체(지도에 남아 계획을 망침)가 훨씬 비싸다. 원본 SAM-6D 는 벤치마크용으로 "항상 답하는" 구조라 이 비용을 다루지 않는다.
- **기여 1. 이름 붙은 배타적 가설 생성** (YOLO-World 문구 상자 + 관문 AND + 독점 배정). 후보마다 "어느 물체인가"가 붙고 상자·물체가 1:1 로만 맺어져 중복과 이름 혼동이 구조적으로 사라진다. 기하 점수 대신 색상 관문을 넣어 특징 모델이 못 가르는 닮은 쌍을 가른다. 세 관문은 합산이 아니라 AND 라서 "답하지 않음"이 가능하다.
- **기여 2. 가설 집합 위의 자세 검증** (PEM 기하 1위 채택 → 윤곽·무늬·합의 검증). PEM 의 300개 가설을 버리지 않고, 깊이만 보는 기하 점수가 못 보는 색 영상 증거(실루엣·질감)와 가설 간 합의로 채택 여부를 결정한다. 틀린 인식·틀린 자세는 여기서 "답 없음"이 된다. 오답 0.114 → 0.028 과 같은 물체끼리 ADD-S AUC 95.8 → 97.2 의 출처.
- **기여 3 (선택). 느슨한 제안 + 엄격한 검증의 분업.** 배정 대안과 완화 관문은 인식 단계 오답을 늘리지만(0.264 → 0.433) 검증이 대부분 걸러 재현율만 되살린다(36장 58.2 → 76.4%). "인식은 재현율을, 검증은 정밀도를 맡는다"는 분업으로 설명하면 배정 대안이 자연스럽게 들어간다. 실제 데이터 오답 4건을 함께 적고 "오답 무허용 현장에서는 끈다"고 쓴다.

#### 10.4 실험 구성 (이미 있는 결과로 충분)

1. **단계별 사다리 L0 → L4** (06 문서): 어느 단계가 재현율을 깎고(문구 상자 −15%p, 독점 배정 −18%p) 어느 단계가 오답을 줄이는지(관문 0.226 → 0.114, 검증 → 0.028).
2. **판정 방식 비교** (07 §3.12, 12 문서): 같은 앞단에서 원본 판정 대 관문. "인식 단독으로는 원본 0.5 가 낫다"를 **스스로 보여 주고**, 검증을 붙인 36장에서 역전됨을 보인다. 이것이 가장 설득력 있는 배치다.
3. **검증 켬/끔** (10 문서 2-1·2-2): 찾는 수는 같고 오답만 5 → 42, 0 → 4. 검증이 오답을 책임진다는 직접 증거.
4. **실시간 지도** (13 문서): 실제 영상 5개 39/40·오답 4(개선안 3 은 0), YCB-V 오답률 35.7 → 19.7%.
5. **개선안 3** (FastSAM 앞단 + 우리 검증, 08 §4·§7): "검증은 앞단에 독립적으로 효과가 있다"는 일반성 주장. 기여 2 를 강하게 만든다.
6. **ViT-S/ViT-L** (12 문서): 특징 모델 크기는 문구 상자 위에서 거의 영향이 없음 → 작은 모델로 충분하다는 근거.

#### 10.5 표현

- 피할 표현: "빠르다", "인식 정확도가 높다", "원본을 능가한다".
- 쓸 표현: "정밀도 우선(precision-first)", "답하지 않을 수 있는 구조(abstention)", "같은 시간 예산 안에서 검증을 수행", "같은 물체끼리는 자세가 더 정확", "지도에 틀린 항목이 남지 않음".

### 11. 개선안 3 + 군집 먼저를 주 내용으로 할 때의 논문 뼈대 (2026-10-07 추가)

10절의 논리를 "원본 앞단 + 자세 검증"으로 좁힌 판입니다. 수치는 16 문서(900장)·15 문서(실시간)·E 묶음 프로파일에서 가져왔습니다.

#### 11.1 주장 → 기여 → 증거

**문제.** 벤치마크용 6D 자세 추정기는 물체마다 반드시 답을 냅니다. 로봇 지도에서는 못 찾은 물체보다 틀린 물체가 비싸고, 한 번 올라간 틀린 항목은 지도에 남습니다.

**기여 1 — 가설 집합 검증(hypothesis-set verification).** PEM 이 내는 자세 가설 300개를 기하 점수 1위로 뭉개지 않고, 깊이가 보지 못하는 색 영상 증거(실루엣 IoU, 질감)와 가설 간 합의로 채택 여부를 결정한다. 통과 가설이 없으면 답하지 않는다(abstention). 학습 없음, 모델 가중치 변경 없음, 입력 조건은 원본과 같음(CAD 만).

**기여 2 — 군집 먼저 검증(cluster-first verification).** 300개 가설을 자세 공간에서 먼저 묶어 군집 대표만 렌더·검사하고, 합의는 군집 크기로 가중한다. 합의가 모자란 물체만 전체 검증으로 되돌린다. 900장에서 답이 99% 동일, 장당 342 → 240 ms; 36장 검증 143 → 54 ms; 실시간 260901 6.17 → 7.49 Hz.

**증거.**
- 검증 켬/끔 대조군(개선안 2 대 3, 같은 앞단): 900장 오답 0.232 → 0.049/장, 찾은 비율 86.9 → 80.8%; YCB-V 실시간 잘못 173 → 36, 찾은 55 → 53; 260901 오답 4 → 0~1. "검증은 재현율이 아니라 오답을 바꾼다"를 한 표로.
- 원본 대비(개선안 3 + 군집 먼저): 900장 오답 0.308 → 0.051(1/6), 정답 비율 93.2 → 98.6%, 같은 물체끼리 ADD-S 94.6 → 96.7, 장당 530 → 240 ms; 260901 3회 평균 처리율 3.63 → 7.54 Hz, 최종 지도 6.7/2.3 → **8.0/0.0**(세 번 모두 8/0); 실제 영상 5개 최종 지도 오답 8~12 → 0(노트북). **YCB-V 실시간은 3회 평균으로 찾은 53.7 → 54.0, 잘못 46.7 → 43.7(실행 간 폭이 겹침), 지도 ADD-S 89.2 → 90.7, 처리율 1.76 → 3.14 Hz** — YCB-V 에서 오답 억제의 근거는 원본 대비가 아니라 검증 켬/끔 대조(173 → 36~47)에서 가져올 것(15 문서 4-4절).
- 일반성: 같은 검증을 문구 상자 앞단(개선안 1·배포)에 붙여도 같은 방향(13·15 문서) → 검증이 앞단에 독립적.
