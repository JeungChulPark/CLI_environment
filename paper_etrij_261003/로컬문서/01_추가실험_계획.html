논문을 위한 추가 실험 계획

작성일 2026-10-03. 지금 있는 실험(원고 6절)으로 무엇이 증명되었고 무엇이 비어 있는지 나눈 뒤, 비어 있는 부분을 채울 실험을 우선순위대로 정리했다.

1. 지금 실험이 증명하는 것과 빈 곳

주장 지금 근거 빈 곳 (심사에서 물을 것)
촬영 시각 키프레임 고정이 지도 보정을 흡수한다 실행 기록 61회 재생, 등록 방식 (a)~(d) 비교 (8,964건, 보정이 끼어든 130건) ① 정답 좌표 대비 절대 오차가 없다 (지금은 같은 물체 관측의 일관성만 있다) ② 지연 길이에 따라 효과가 어떻게 변하는지 곡선이 없다 ③ LiDAR SLAM에서 같은 비교가 없다
두 장치로 나눠야 SLAM이 실시간을 지킨다 같은 장치에 부하가 걸리면 자세 전달 지연이 0.04 → 2.5초 (한 번 측정) 한 장치에서 SLAM과 인식을 함께 돌린 기준 실험이 체계적이지 않다 (프레임 누락, 궤적 오차, 객체 지도 오차)
시간 정렬과 외부 파라미터가 정확하다 정지 물체 흩어짐 5.6 → 1.5 cm, 잔차 0.41 cm 시각 오차(τ)를 일부러 틀렸을 때 얼마나 나빠지는지 민감도가 없다
인식기가 빠르고 틀린 답이 적다 한 장 비교 (YCB-V, YCB-M, 실내), 관문 효과 실험 다른 제로샷 방법(FoundPose, GigaPose, FoundationPose 등)과 같은 조건에서 비교하지 않았다. GPU가 실험마다 다르다
객체 기억과 재연결 실내 2회 72/74, YCB-M 101건 같은 종류 물체가 여러 개인 장면이 없다. 물체를 옮기는 장면이 없다
지연 보상 표시 YCB-V·YCB-M 화면 일치율 실제 주행에서는 정답이 없어 화면 일치율을 재지 못했다
실시간 동작 녹화를 두 장치에서 1배속으로 재생 카트에서 카메라를 직접 받아 실행한 기록이 없다

2. 필요한 실험 (우선순위 순)

꼭 필요 (P1): 심사 통과에 직접 영향

# 실험 방법 얻는 수치 새 녹화
E1 정답이 있는 실내 주행 apriltag_gt/GT_APRILTAG_GUIDE.md대로 태그 8~20개와 물체 8종의 위치를 측량한다. 물체 바닥에도 태그를 붙여 물체 정답을 만든다. 같은 경로를 2~3회 주행한다 물체 위치 절대 오차(중앙값, 90%), 카메라 궤적 앵커 오차, 등록 방식 (a)~(d)의 절대 오차 필요 (2~3회)
E2 지연 길이 실험 objpose/pc/anchor_ablation.py 재생에서 인식 결과 도착 시각을 인위적으로 0, 0.5, 1, 2, 4, 8초 늦추고 (a)~(d)를 다시 계산한다 지연-오차 곡선 4개. "지연이 길수록 (d)만 버틴다"를 그래프로 보인다 불필요
E3 한 장치 대 두 장치 같은 녹화를 ① 한 장치에서 SLAM과 SAM-6D를 함께 실행, ② 두 장치로 나눠 실행한다 SLAM 처리 프레임 비율, 추적 실패 횟수, 루프 보정 크기, 객체 흩어짐, 중복 수 불필요
E4 같은 GPU에서 제로샷 방법 비교 YCB-V BOP 평가 목록에서 SAM-6D, 제안 방법, 그리고 공개 코드가 있는 1~2개(FoundPose 또는 GigaPose, CNOS+SAM-6D PEM)를 같은 GPU로 실행한다 BOP AR, 장당 처리 시간 (논문 보고값과 같은 조건 비교) 불필요
E5 반복 통계 주요 수치(표 2, 표 3, 화면 일치율)를 실행별로 나눠 평균 ± 표준편차 또는 95% 신뢰구간을 낸다 오차 막대, 유의성 불필요 (기존 113회 기록)

있으면 좋음 (P2): 범용성과 견고성

# 실험 방법 얻는 수치
E6 LiDAR SLAM 등록 방식 비교 HDL-Graph-SLAM 실행 기록으로 (a)~(d)를 다시 계산한다 표 2의 LiDAR 판. "SLAM 방식과 무관"을 보인다
E7 네트워크 지연·손실 주입 Linux tc netem으로 지연 50~500 ms, 지터, 손실 1~5%를 넣는다 대기 목록 등록률, 적응형 표시 지연, 자세 없는 표시 프레임 비율
E8 시각 오차 민감도 τ를 ±10, 20, 50, 100 ms만큼 일부러 틀리게 넣는다 흩어짐-τ 곡선. 메타데이터 시각과 오프셋 추정이 왜 필요한지 보인다
E9 카트 실시간 실행 녹화 재생 대신 카메라를 직접 받아 1~2회 실행한다 "재생이 아닌 실제 실시간"이라는 근거, 장치 자원 사용량
E10 처리 시간 분해 모듈별 시간(후보, 관문, PEM, 검증, 등록, 표시)과 GPU·CPU 사용량을 잰다 처리 시간 표, 병목 설명

한계를 줄이는 실험 (P3): 후속 논문으로 미뤄도 됨

# 실험 내용
E11 같은 종류 물체 여러 개 같은 물체 2~3개를 배치해 연결 성능을 본다 (지금은 미평가로 적혀 있다)
E12 물체 이동·제거 주행 중 물체를 치우거나 옮겨 삭제·재등록 동작을 정량화한다
E13 가림 정도별 가림 30~50% 구간이 약점(3%)이므로 개선안과 함께 실험한다
E14 잘못된 루프 보정 검출 40회 중 2회 망가진 지도를 자동으로 판정하는 방법(LiDAR 궤적과 비교 등)

3. 권장 순서

  1. 새 녹화 없이 할 수 있는 실험을 먼저 한다. E2(지연 곡선), E5(통계), E3(한 장치 대 두 장치), E6(LiDAR 판)은 기존 기록과 도구로 할 수 있고, 원고의 약점을 가장 많이 메운다.
  2. E4(같은 GPU 비교)는 공개 코드를 설치해야 하지만 새 녹화가 필요 없다.
  3. E1(AprilTag 정답 주행)은 준비(인쇄·측량)가 필요하다. 논문의 신뢰도를 가장 크게 올리므로 IROS 마감(2027년 3월) 전에 끝내는 것을 목표로 한다.
  4. E7~E10은 E1 녹화 때 함께 기록한다.

주의: E3의 "한 장치" 실행은 논문의 비교 기준(baseline)으로만 쓴다. 특허 문서에는 넣지 않는다 (특허는 두 장치 분리를 전제로 한다).
