F. 공간 객체 상태 지도를 위한 논문 비교

개별 문서 19~23(2026-10-09 ~ 10-10)을 요약했습니다. 공간 객체 상태 지도를 두고 제안 방법과 기존 논문 두 편(FM-Fusion, DualMap)을 세 데이터에서 비교한 결과와, 그 비교를 위해 원고·실험 환경에서 한 일을 한 문서로 모았습니다. 장비는 모두 노트북 RTX 3080 Ti Laptop 이고 확인용입니다. 최종 수치는 RTX 5090 에서 다시 냅니다. 원문은 개별문서/ 의 19~23 문서이고, 각 절 끝에 출처 문서를 적었습니다.

2. 실험 구성

2.1 세 데이터

데이터 내용 카메라 궤적 정답 채점
YCB-V 시험 영상 12개(48~59, 21k 프레임), 정적 장면 세 방법 모두 같은 정답 궤적 (SLAM 오차를 빼고 지도만 비교) 정답 자세의 CAD 표면 중 실제로 보인 부분 같은 종류끼리 3D IoU(1 cm 복셀) 헝가리안 배정, IoU ≥ 0.25 면 맞음. 보조로 중심 5 cm
ObChange-Kitchen 같은 부엌 6번 방문(각 약 50초), 방문마다 YCB 물체 배치가 바뀜. TU Wien 데이터 중 Kitchen 만 씀 데이터셋 /tf 궤적 YCB-V CAD 모델이 있는 물체 25개, CAD 모델을 정답 점군에 ICP 로 다시 맞춤 중심 5 cm (3D IoU 는 정답 점군 흔들림 때문에 보조)
실 데이터 우리 로봇 녹화 5개(128~314초), 물체 8개씩 제안 방법 실시간 실행의 Mac ORB-SLAM3 궤적을 세 방법이 같이 씀 물체 정답 없음. 이전 실행들의 물체 위치 중앙값을 기준으로 씀 종류가 맞고 기준에서 20 cm 안이면 맞음. 점수 = 맞음 ÷ (8 + 잘못)

2.2 처리 조건

  • 제안: 실제 허브를 1배속 실시간으로 돌려, 처리할 수 있는 인식 프레임만 씁니다(인식 1.5~3.5 Hz). YCB-V·ObChange 에서는 SLAM 대신 정답 궤적을 흘려 넣었습니다.
  • FM-Fusion · DualMap: 오프라인으로 10프레임마다 처리했습니다. 기준 방법에 유리한 조건입니다.
  • 출처: 20 문서 1절, 21 문서 1~2절, 23 문서 1~2절.

2.3 기존 방법을 원 설정과 다르게 돌린 부분 (논문 각주용)

FM-Fusion 1. 라벨: RAM 태그 대신 고정 글 문구, 닫힌 클래스를 대상 물체로 바꾸고, 라벨 혼동 행렬은 단위 행렬로 둠(이 문구에 대한 혼동 통계가 없음). 2. 크기: 복셀 0.02 → 0.01, sdf_trunc 0.04 → 0.02, 최소 점 500 → 50. 기본값으로는 YCB 물체가 모두 걸러져 지워집니다. 민감도는 아직 보지 않았습니다. 3. ObChange 누적 입력(4,484~8,974장)을 위해 지도 생성 프로그램의 "4,000프레임 초과 시 종료" 상한을 20,000 으로 올려 다시 빌드(알고리즘은 같음).

DualMap 1. 찾을 물체 목록을 대상 물체 글 문구 + unknown 으로 바꾸고, 실행 화면 표시(rerun)를 끔. 나머지는 저장소 기본 설정(구체 지도만). 2. 입력을 Replica 형식으로 변환(PNG → JPEG q95). 3. 두 판을 싣습니다. "공개 설정"은 공개 코드 그대로(재현성 기준)이고, "BGR 수정"은 색 순서 하나만 고친 판입니다. DualMap 은 영상을 RGB 순서로 넘기는데 YOLO-World · MobileSAM · FastSAM 을 돌리는 ultralytics 는 BGR 로 읽어, 공개 코드 그대로면 빨강과 파랑이 뒤바뀐 영상으로 찾습니다. 고치면 YCB-V F1 이 0.091 → 0.168 로 오릅니다. 20 문서는 BGR 수정 판을 주 행, 공개 판을 각주로 두기를 권했습니다. 4. 지도에 unknown 으로 남은 물체는 어떤 물체라고 주장하지 않으므로 채점에서 뺌.

  • 출처: 20 문서 4절, 21 문서 5절, 23 문서 2.2절.

5. 논문에서의 쓰임

  1. 7장에 "객체 지도 비교" 절을 넣습니다. 0절의 세 데이터 비교표와 1절의 방법 비교표가 본문 표의 후보이고, 2.3절이 각주입니다.
  2. 주장할 수 있는 것: 최종 지도의 정확도(맞게 올린 물체가 많고 잘못이 적음), 6D 자세를 가진 지도, 3D 일치도(YCB-V), 새 물체를 올리는 속도(ObChange).
  3. 아직 주장하지 않는 것: 치운 물체를 지우는 변화 반영. 존재확률 설정을 확인하기 전에는 쓰지 않습니다.
  4. 실시간 정확도의 재현성: 22 문서의 3회 반복(두 GPU 에서 6번 모두 8 / 0)을 본문이나 각주로 덧붙일 수 있습니다. 녹화 실행의 인식 장치가 이 노트북이라 실제 운용 조건을 보여 줍니다.

6. 한계

  • 실 데이터의 기준 위치가 제안 방법의 이전 실행에서 나왔습니다. 물체 정답이 없어서이고, 반경 20 cm 로 위치 표현 차이(수 cm)는 흡수되지만 독립 정답은 아닙니다.
  • 글 문구는 한 번 정한 것만 썼습니다. 문구를 넓히면 기준 방법의 재현율은 오를 수 있지만 잘못도 함께 늘어나는 관계입니다.
  • 처리 조건이 다릅니다. 제안은 실시간, 기준 방법은 오프라인 10프레임마다입니다(기준 방법에 유리).
  • 실 데이터에는 물체를 치운 장면이 없습니다. 변화 반영은 ObChange 로만 확인했습니다.
  • SLAM 루프 오결합: 같은 녹화(260901)에서 3 m 넘는 잘못된 루프 보정이 나와 해당 실행을 버렸습니다. 키프레임 고정 지도는 잘못된 보정도 따릅니다.

7. 남은 일

  1. 제안 방법 존재확률 민감도: 기록된 인식 결과를 재생하면 GPU 없이 P_D · c 만 바꿔 ObChange 연속 지도를 다시 만들 수 있습니다. 치운 물체가 지워지는지, 대신 시야 밖 물체를 잘못 지우지 않는지 확인합니다.
  2. DualMap 전체 설정(추상 지도 포함) 으로 연속 지도를 다시 돌려 변화 반영이 동작하는지 확인합니다.
  3. FM-Fusion 크기 설정 민감도(복셀 0.015 등)를 확인합니다.
  4. DualMap 주 행을 공개 설정과 BGR 수정 중 어느 쪽으로 할지 정합니다.
  5. RTX 5090 최종 실행: 세 데이터를 같은 GPU 에서 다시 돌리고 처리 속도도 함께 잽니다. FM-Fusion 은 GroundingDINO 를 CUDA 12.8 이상으로 다시 빌드해야 합니다.
  6. 원고 [verify] 항목: 7.2절 재연결 실험의 존재확률 값(9월 19일 전 0.15 / 0.03 인지), 측정 검출률 6~20% 의 출처, 녹화 실행의 GPU.
  7. 개선안 3 인식기 구조 그림(v0.2 그림 4 자리).
