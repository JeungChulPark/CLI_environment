## 1. 데이터와 기준 궤적

- `260901_cbnu_bigeightcircle`: 315 s, SLAM 카메라 9445 프레임(30 Hz, Husky), VLP-16 3124 스캔(10 Hz), xsens 63013 샘플(200 Hz).
  카메라·라이다·IMU 헤더 스탬프는 같은 호스트 시계라 서로 3 ms 안에 맞는다(`calib_rig.py`, |ω| 상호상관).
- 로봇은 처음 28 s 를 **직진**하고(정지 구간이 없다) 이후 큰 8자를 4바퀴 돈다: 경로 64 m, 누적 yaw 1444°.
- 기준 = KISS-ICP(`kiss_gt.py`: `lidar_stream.py` 와 같은 설정, 2-pass deskew). 귀환 오차 15 cm, yaw 는 자이로·ORB 와 0.2°
  안에서 맞지만 **pitch/roll 은 약하다**(0.6~0.9°/30 s). 그래서 비교는 위치와 yaw 위주.
- 카메라–라이다 RT 는 2 s 상대운동 hand-eye 로 데이터에서 추정(`T_lidar_cam`, 회전 잔차 0.36°, 이동 1.5 cm; 평면 주행이라
  수직축 lever arm 은 관측 불가, 비교에 영향 없음). 카메라–IMU 회전은 각속도 벡터 정합: 거의 축 치환
  (cam x = imu y, cam y = imu z, cam z = imu x), 주축 일치 0.007°.

## 2. 보정 방식 — "자이로 보조 ORB-SLAM3" (RGB-D 모드 유지)

ORB-SLAM3 의 IMU_RGBD(시각-관성) 모드는 쓰지 않았다. 가속도계·속도·중력·바이어스 상태를 초기화해야 하고 지상 로봇의
등속 주행에서는 그 초기화가 자주 실패한다. 대신 자이로만 **회전 제약**으로 넣었다.

1. 스트리머(`gyro_aid.h`, `slam_stream --gyro rig.json [--imu DIR]`)가 IMU bag 을 읽어 프레임마다 자이로만 적분한
   카메라 자세 `R_gc` 를 `System::SetFrameGyro()` 로 넘긴다. ORB-SLAM3 는 두 프레임의 차 `R_ci_cj = R_gc_i^T R_gc_j` 만 쓴다.
2. `Tracking`: 등속 모델의 회전을 자이로 회전으로 바꾸고(카메라 중심 이동은 유지), `PoseOptimization` 에
   회전 prior 에지(`EdgeGyroRotPrior`, σ = `Gyro.SigmaFrame` 5e-4 rad/프레임)를 추가.
3. `LocalBundleAdjustment`: 창 안의 키프레임을 시간순으로 이웃끼리 자이로 상대회전 에지(`EdgeGyroRelRot`)로 묶는다.
   σ² = SigmaKF² + SigmaARW²·dt + (SigmaRate·dt)² + (SigmaScale·각도)² (기본 5e-4 rad, 2e-4 rad/√s, 1e-4 rad/s, 1e-3; 최대 간격 10 s).
4. **바이어스가 핵심**이다. 바이어스 오차 3e-4 rad/s 면 5 분에 yaw 5° 가 쌓인다(1차 버전이 실제로 그랬다). 카메라가
   3 s 동안 2° 이상 돌지 않은 구간(정지 또는 직진)마다 `(자이로 회전 − 시각 회전)/T` 로 바이어스를 다시 재고 최근 20 창의
   이동평균을 쓴다. 직진 중 시각 회전은 같은 맵점을 계속 보므로 수 0.01° 정밀이고 드리프트와 섞이지 않는다.
   시작값은 rig json(`gyro_bias_rad_s`), 첫 창(3 s)에서 바로 대체된다.
5. 설정 키 `Gyro.Use / SigmaFrame / SigmaKF / SigmaARW / SigmaRate / SigmaScale / MaxGapS` 는 `--param` 으로 바꿀 수 있다.

## 3. 같이 고친 ORB-SLAM3 원본 버그 두 가지 (실시간 재생에서만 드러남)

| 버그 | 증상 | 수정 |
|---|---|---|
| `KeyFrameDatabase::DetectNBestCandidates` 마지막 루프의 `if(isBad()) continue;` 가 반복자를 전진시키지 않음 | 후보 키프레임이 컬링되면 루프 클로저 스레드가 100 % CPU 로 영원히 돌고 **그 뒤로 루프가 한 번도 안 닫힌다**(실시간 3회 중 2회, 종료 시 "background threads still busy") | `i++; it++;` 뒤에 `continue` |
| `KeyFrame::isBad()` 가 `mMutexConnections` 를 잡음 → `UpdateBestCovisibles()`(자기 뮤텍스 보유) 안에서 이웃의 `isBad()` 호출 | LocalMapping 컬링과 LoopClosing `SetErase` 가 이웃 키프레임을 동시에 `SetBadFlag` 하면 AB/BA **교착**, 추적까지 멈춤(`.3` 에서 2/2, gdb 스택으로 확인) | `mbBad` 를 `std::atomic<bool>` 로, `isBad()` 무잠금 |

두 버그 모두 자이로와 무관하며, 실시간 속도(pace 1.0)로 315 s 세션을 돌릴 때 나타난다. 느린 재생(NFS 에서 0.6배속)에서는 보이지 않았다.

- 루프가 닫히는 순간(≈113 s) 기본 ORB 의 live 포즈는 1~2 s 동안 수십 cm 튄다(loop 보정 직후 추적 과도기). 자이로 prior 가
  있으면 이 과도기가 크게 준다 — 최대 오차 차이의 대부분이 여기서 온다.
- 기준 자체 오차가 수 cm 이므로 ATE 1 cm 안팎의 차이는 유의하지 않다. 유의한 것: 최대 오차·yaw 최대·1 s 상대 오차(추적 흔들림)·루프 없는 구간의 드리프트.

## 6. 남은 것

- 다른 세션(eightcircle/digut/longcircle, 260910/260915)에는 같은 rig json 을 그대로 쓸 수 있는지(IMU 장착이 같다면 R_cam_imu 동일) 확인 후 UI 에 IMU 토글을 넓힐 것.
- `isBad()` 수정 뒤에도 `.3` 에서 자이로 실행 1회가 2500 프레임쯤에서 전체 스레드 정지(교착)했다. gdb 감시 실행 8/8 에서는 재현되지 않아 스택을 못 잡았다;
  다른 잠금 순서 역전이 하나 더 있을 수 있다. `rt/260901/bigeight/dbg_hang_host.sh` 로 재현을 계속할 것.
- 루프 보정 직후 live 포즈 과도기(기본 ORB 1~2 s 수십 cm)의 근본 원인은 아직 보지 않았다.
- 자이로 에지는 LocalBA 까지만; GBA/에센셜 그래프에는 넣지 않았다(루프 보정 자체는 시각 정보로 충분).
- bigeightcircle 의 SAM τ(−208 ms, eightcircle 값)는 이 세션에서 검증하지 않았다(객체 융합에만 영향).
