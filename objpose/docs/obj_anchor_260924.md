# 객체 기준점으로 SLAM 현재 위치 보정 (Object Pose Map → SLAM, 2026-09-24)

지금까지는 SLAM 자세로 객체를 지도에 올리는 한 방향이었다. 이 작업은 반대 방향을 더한다.
지도에 여러 번 관측돼 확정된 객체를 고정 기준점으로 삼고, 새 SAM-6D 결과가 그 객체를 볼 때마다
"객체가 등록된 자리에 있으려면 카메라가 어디 있어야 하는가"로 SLAM 현재 위치를 고친다.

## 구현 (기존 파일은 수정 없음)

| 파일 | 내용 |
|---|---|
| `objpose/pc/obj_anchor.py` | `ObjectAnchor`. 3초·12프레임 슬라이딩 창에서 보정 변환 C 하나를 푼다: 창 안의 SLAM 상대 이동은 그대로 두고, 객체 관측(위치 + 비대칭 물체는 방향)과 C의 랜덤워크 사전 조건으로 최소제곱(Huber, 4σ 이상치 제거 후 재풀이). 서로 다른 객체가 3개 이상일 때만 회전도 보정(점 3개가 있어야 회전이 정해짐), 아니면 위치만. 기준점은 관측 5회가 된 순간의 객체 자세로 고정(`freeze`) — 이후 평균에 섞이는 드리프트를 따라가지 않게. 출력: T_corrected(t) = C · T_slam(t) |
| `objpose/pc/anchor_memory.py` | 보정된 카메라 자세를 그대로 받는 ObjectMemory (평가용) |
| `objpose/pc/hub_anchor.py` | hub.py를 감싸 실행. 객체 메모리만 보정 버전으로 바꾸고 화면은 보정된 카메라 자세로 그림. CLI는 hub.py와 같고 `--anchor-set k=v`, `--anchor-off` 추가. 결과: `anchor_log.jsonl`, `anchor_summary.json` |
| `objpose/tools/obj_anchor/eval_ycbv.py` | YCB-V 12장면, 실시간 순서(done_s) 재생, GT 카메라와 비교 |
| `objpose/tools/obj_anchor/eval_real.py` | 실제 주행 기록(hub 로그) 재생. 기준 = 주행 뒤 최종 키프레임 궤적 |
| `objpose/tools/obj_anchor/replay_slam_log.py` | 기록된 ORB-SLAM3 메시지를 원래 프로토콜로 실시간 재전송 (SLAM 호스트 없이 허브 실시간 검증) |

`hub.py`, `fusion.py`, `memory.py`는 바뀌지 않았다(작업 전 사본과 byte 비교). 되돌리려면 `hub_anchor.py` 대신 `hub.py`를 실행하면 된다.

## 추가: 외부 파라미터 X가 원인인가? (`tools/obj_anchor/fit_extrinsic.py`, `spread_parts.py`)

최종 SLAM 궤적으로 모든 SAM-6D 추정을 지도에 놓고, 같은 물체의 추정이 한 점에 모이도록 X 보정(회전·이동), 거리 척도, 시간 오프셋을 추정.
추정에 쓰지 않은 주행으로 평가(260915 리그: dense·distance·eightcircle·height로 추정 → inlong·outlong 4개 평가; cbnu: 다른 실행 3개로 추정 → r1 평가).

| 그대로 | 22.4 / 23.5 / 17.5 / 30.9 | 24.1 |
| X만 보정 (0.6°, 1.3 cm) | 16.5 / 19.9 / 16.6 / 21.4 | 20.6 (0.35°, 1.8 cm) |
| 거리 척도만 (×0.971) | 13.3 / 16.2 / 16.0 / 15.4 | 23.1 (×0.993) |
| X + 척도 (×0.940, 0.6°, 3.8 cm) | **12.5 / 14.2 / 10.6 / 19.4** | **17.8** (×1.042, 0.5°, 6.3 cm) |

* X 자체의 오차는 작다(0.3–0.6°, 1–2 cm). 260915 리그는 SAM-6D 거리와 SLAM 지도 척도가 약 6% 어긋나는 것이 더 크다
  (퍼짐의 61–70%가 시선 방향, 멀수록 커짐: +43–73 mm/m). 짧은 시간(0.5 s) 흔들림은 5–10 mm.

* X + 척도를 넣어도 cbnu의 "현재 위치가 SLAM 궤적에서 멀어지는" 현상은 그대로(113 → 147 mm). 즉 그 원인은 X가 아니다.
  - 보정 C가 2–6.6° 회전한다(SLAM 실제 회전 오차는 0.16°). 아래 "원인 판별"에서 확인.
  - 회전을 꺼도 약 7 cm가 남는다. 기준점을 고정한 시점(0–25 s)의 실시간 SLAM 위치가 루프 클로저 전이라 최종 궤적과 23–72 mm 달랐고,
    평가용 보정 메모리는 키프레임 고정을 쓰지 않아 ORB-SLAM3의 이후 루프 보정을 기준점이 받지 못한다 → 보정이 카메라를 옛(드리프트된) 좌표로 끌어간다.

## 원인별 수정과 재검증 (2026-09-25)

채택한 구성 (`obj_anchor.py` 옵션, 기존 기본값은 그대로 두고 옵션으로 켬):
* 회전: 물체 방향 관측 안 씀(`use_rotation=false`), 창의 물체 위치로 회전이 1σ 2° 안으로 정해질 때만 회전 보정(`max_rot_sigma=2`).
* 기준점 불확실성 = 리그별 측정값: YCB-V `sig_obs_t0=0.003, sig_obs_tz=0, deadband_m=0.003`, 실제 리그 `sig_obs_t0=0.03, deadband_m=0.03`.
