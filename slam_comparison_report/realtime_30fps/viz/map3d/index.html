Halving the input rate changed the map almost not at all

Path length differs by 5 cm in 37 m (0.13%) and the start-to-end closure gap by 1 mm. On an eight-figure course that returns to its origin, that closure gap is the accumulated drift — so both runs drifted by the same ~27 cm over 37 m, roughly 0.7% of path length.

The half-speed run did build a slightly denser map (159 keyframes and 12.6k points against 152 and 12.1k). More wall-clock time per frame lets Local Mapping finish more of its work between frames, so marginally more keyframes survive culling — but it bought no measurable accuracy.

The two scenes are not in a shared coordinate frame

ORB-SLAM3 starts each session's map at identity from its own first frame, so a pose-by-pose difference between the runs would measure nothing but that arbitrary origin. Each scene is drawn in its own frame; only scale-independent quantities are compared above. The world axes follow the first camera's optical frame — +x right, +y down, +z forward — so the viewer treats xz as the ground plane and -y as up.

Both runs also created two maps: tracking was lost once and re-initialised. The point cloud here is what GetAllMapPointsWorld() returned at shutdown.
