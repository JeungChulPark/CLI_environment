What counts as an error here

The state comes from ORB-SLAM3's own eTrackingState, recorded per frame: OK, RECENTLY_LOST (the local map was lost, recovery still being attempted), LOST (relocalisation needed), and the initialising states. A separate flag marks frames where TrackRGBD() returned no pose at all. Map resets — where the Atlas abandons the current map and starts another — are read from the run log, and the trajectory is drawn broken at the pose jumps they cause.

SLAM is not running in this page. Trajectory, map and timings are from a measured run on this machine (CPU only, no CUDA); they are replayed in sync with the frames that produced them. Playing at 2× speeds up the replay, not the tracker.
