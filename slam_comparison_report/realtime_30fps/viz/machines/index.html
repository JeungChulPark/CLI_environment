Read these before comparing

The Mac ran the harder schedule

WSL2's table replayed the bag at its recorded pace, about 25 Hz over 285 s. The Mac run forced 30 Hz, finishing the same frames in 238 s, with a five-deep drop-oldest queue. No frame was dropped.

Different input paths

On WSL2 a Python ROS 2 bridge in its own process aligned depth at about 8 ms per frame. On the Mac a C++ reader in the same process reads the .db3 directly and aligns in about 2 ms. Both time only the TrackRGBD() call, but WSL2's tracker had more work competing beside it.

What was held equal

  • ORB-SLAM3 source: the repository tree for A/B/C, f912e95^ for baseline
  • Settings: orbslam_ws/data/nf2000_*.yaml
  • -O3, native CPU tuning, four ORB-extraction threads, OMP_NUM_THREADS=6, stage timers on
  • Pairing rules, depth alignment and monotonic 1/30 s timestamps as in rs_bag_bridge.py

What was not

  • Compiler: conda GCC with AVX2 on WSL2, Apple Clang with NEON on the Mac
  • The Mac tracking thread ran at QoS USER_INTERACTIVE, which keeps it on performance cores. WSL2 cannot tell P-cores from E-cores.
  • Per-frame WSL2 data is not in this checkout, so WSL2 appears here as published summaries only
