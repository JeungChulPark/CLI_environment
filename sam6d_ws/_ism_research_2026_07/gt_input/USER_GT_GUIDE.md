# 가시성 GT 입력 안내

이 폴더는 **ldh 님이 직접 채우는 유일한 파일**을 담고 있습니다.
전체 2,596 프레임 중 **339 프레임(13.1%)** 만 보시면 됩니다.

---

## 1. 무엇을, 왜 채우는가

지금까지의 모든 정확도 분석은 **"모델이 검출한 것"** 위에서만 이뤄졌습니다.
그래서 *"실제로 객체가 있는데 모델이 후보조차 만들지 못한 경우(proposal miss)"* 를
셀 수 없었습니다 — 검출에서 출발하면 검출이 놓친 것은 원리적으로 보이지 않기 때문입니다.

필요한 것은 딱 하나입니다: **검출과 무관하게 고른 프레임에서, 사람 눈에 실제로 무엇이 보이는가.**

BBox(사각형 좌표)는 **요구하지 않습니다.** 이름만 적으시면 됩니다.

## 1.5 시작하는 법 — 뷰어 (권장)

CSV 를 직접 편집하지 마시고 뷰어를 쓰십시오. 타이핑이 없어 **오타가 원천적으로 불가능**하고,
모델 판정이 기본으로 숨겨져 편향 위험도 없습니다.

```bash
cd sam6d_ws/_ism_research_2026_07/gt_input
python3 serve_gt.py
```

그러면 터미널에 주소가 뜹니다. 브라우저에서 여십시오.

```
http://127.0.0.1:8765
```

- 표준 라이브러리만 씁니다. **numpy·opencv·flask 설치 불필요**, 아무 `python3` 로나 실행됩니다.
- `127.0.0.1` 에만 열리므로 외부에서 접근할 수 없습니다.
- 첫 실행 시 `user_visibility_gt.csv.bak` 백업이 자동 생성됩니다.
- 저장은 클릭할 때마다 **즉시** 이뤄지고, 임시파일 → 교체 방식이라 중간에 꺼도 CSV 가 깨지지 않습니다.
- 껐다 켜면 **미완료 첫 프레임에서 이어서** 시작합니다.
- 종료는 터미널에서 `Ctrl+C`.

**조작**

| 키 | 동작 |
|---|---|
| `1` ~ `9`, `0` | 객체 토글 (버튼에 사진과 이름이 붙어 있습니다) |
| `N` | `none` — 객체 없음 |
| `U` | `unsure` — 판단 불가 |
| `Space` 또는 `→` | 다음 프레임 |
| `Backspace` 또는 `←` | 이전 프레임 |
| `Esc` | 이 프레임 선택 전체 해제 (미완료로 되돌림) |

**화면 상단 옵션**

- **필터**: `우선순위 1 — 균등층 (107)` 이 기본값입니다. 이것만 끝내셔도 핵심 분석이 가능합니다.
- **완료 건너뛰기**: 이미 입력한 프레임을 건너뜁니다 (기본 켜짐).
- **원본 크기**: 작은 객체를 볼 때 1:1 로 확대합니다.
- **현재 모델 판정 보기**: 기본 **꺼짐**. §4 의 편향 문제 때문이며, 균등층에서는 켜지 마십시오.

포트가 이미 쓰이고 있으면 `GT_PORT=8888 python3 serve_gt.py` 처럼 바꿔 실행하십시오.

## 2. 채울 파일 (뷰어를 쓰지 않을 경우)

```
gt_input/user_visibility_gt.csv
```

| 열 | 채우는가 | 설명 |
|---|:---:|---|
| `dataset_name` | ✗ | 데이터셋 이름 (이미 채워짐) |
| `frame_id` | ✗ | 프레임 번호 (이미 채워짐) |
| `image_path` | ✗ | 해당 프레임 PNG 경로 (이미 채워짐) |
| **`visible_objects`** | **✓** | **화면에 보이는 객체 이름을 `;` 로 구분** |
| **`user_reviewed`** | **✓** | **입력을 마쳤으면 `yes`, 아직이면 `no`** |
| `notes` | 선택 | 자유 메모 |
| `_priority` | ✗ | 1 → 2 → 3 순으로 채우시면 됩니다 (§5) |
| `_strata` | ✗ | 이 프레임이 뽑힌 이유 (§6) |
| `_current_ism_accepted` | ✗ | **현재 모델의 판정 (참고용, §4 주의)** |
| `_n_yolo_candidate_objects` | ✗ | 그 프레임에서 후보를 얻은 객체 수 |

### 입력 규칙

```
visible_objects
  - 보이는 객체 이름을 세미콜론(;)으로 구분          예: milk;Bear
  - 아무 객체도 안 보이면                            none
  - 판단할 수 없으면(흐림·너무 작음·애매)            unsure
  - 일부만 확실하면 확실한 것만 적고 notes 에 메모

user_reviewed
  - 입력 완료          yes
  - 아직 안 봄         no   (초기값)
```

**예시**

```csv
dataset_name,frame_id,image_path,visible_objects,user_reviewed,notes
sam_105018,250,/path/frame_000250.png,"milk;Bear",yes,
sam_105018,275,/path/frame_000275.png,"none",yes,
sam_105018,300,/path/frame_000300.png,"unsure",yes,모션블러 심함
```

## 3. 적을 수 있는 객체 이름 (이 10개만)

**대소문자와 밑줄을 그대로** 복사해 주십시오. `Bear` 는 되지만 `bear` 는 안 됩니다.

| 이름 (그대로 복사) | 어떤 물건인가 |
|---|---|
| `Bear` | 갈색 곰인형 |
| `Rabbit` | 흰색 토끼인형 |
| `Dinosaur` | 연두색 공룡인형 |
| `milk` | 우유팩 (서울우유) |
| `choco_hazelnut_high` | 초코하임 갈색 과자 상자 |
| `Febreze_high` | 페브리즈 파란 분무기 |
| `Mugcup_high` | 분홍 머그컵 |
| `saffron` | 샤프란 액체세제 통 (베이지색 손잡이 통) |
| `Sauce_high` | 소스 병 (갈색 몸통 + 회색 뚜껑) |
| `Sikhye_high` | 식혜 금색 캔 |

특수값 두 개: `none`, `unsure`

> 📷 **`OBJECT_REFERENCE.jpg` 를 먼저 열어 보십시오.** 각 이름이 실제로 어떤 물건인지
> 렌더 이미지 1장 + 실사 crop 3장으로 보여 줍니다. 이름만 보고 헷갈릴 일이 없습니다.

**주의할 혼동 쌍** (지금까지 모델이 가장 많이 틀린 조합입니다. 사람 눈으로는 쉽습니다):
- `choco_hazelnut_high` vs **갈색 택배 상자** → 택배 상자는 **객체가 아닙니다.** 적지 마십시오.
- `saffron` vs `Febreze_high` → 샤프란은 베이지/불투명, 페브리즈는 파란 액체가 비칩니다.
- `Bear` vs `Rabbit` vs `Dinosaur` → 색으로 구분하십시오 (갈색 / 흰색 / 연두색).

## 4. ⚠️ 편향 주의 — 반드시 읽어 주십시오

`_current_ism_accepted` 열에 **현재 모델의 판정**이 들어 있습니다.
디버깅에는 편하지만, **이것을 먼저 보고 "맞다/틀리다"를 판정하면 측정이 무효가 됩니다.**

이 GT 의 목적은 모델을 채점하는 것이고, 채점 기준이 모델의 답을 보고 만들어지면
순환 논리가 됩니다. 특히 **`_priority` 1(균등층)** 은 통계의 분모가 되므로 편향이 치명적입니다.

**권장 절차**
1. `_current_ism_accepted` 열을 **숨기거나 지운 사본**에서 작업하십시오.
2. 이미지를 먼저 보고, 보이는 것을 독립적으로 적으십시오.
3. 다 적은 뒤에 비교해 보십시오.

우선순위 3(오차분석층)에서는 참고하셔도 영향이 적습니다.

## 5. 어디까지 채워야 하는가

시간이 부족하시면 우선순위 순으로만 채우셔도 유효한 분석이 가능합니다.

| 우선순위 | 프레임 | 무엇을 얻는가 | 없으면 |
|:---:|---:|---|---|
| **1** | **107** | **proposal recall 의 무편향 분모** — 이 연구의 핵심 미해결 항목 | 아무 것도 확정할 수 없음 |
| 2 | 63 | 후보가 0인 프레임에 실제로 객체가 있었는지 | proposal miss 확정 불가 |
| 3 | 169 | 클래스 혼동·경계 사례의 오차 분석 | 원인 분석만 제한됨 |
| **합계** | **339** | | |

**우선순위 1만 채우셔도(107 프레임) 전체 합산 proposal recall 을 ±5.5 %p 로 잽니다.**
객체별로 비교하려면 ±17.5 %p 라 부족하며, 그 경우 25프레임 간격을 10프레임으로 좁힌
추가 수집이 필요합니다(별도 요청 시 생성해 드립니다).

소요 시간은 프레임당 30초 가정 시 우선순위 1이 약 **1시간**, 전체가 약 **3시간**입니다.
(실제 속도는 측정된 값이 아니라 가정입니다.)

## 6. 프레임이 뽑힌 이유 (`_strata`)

한 프레임이 여러 이유로 뽑혔으면 문자가 겹쳐 표기됩니다 (예: `UZ`).

| 코드 | 층 | 선정 기준 | 개수 |
|:---:|---|---|---:|
| `U` | 균등 | 각 데이터셋 **25프레임마다** 기계적으로 | 107 |
| `Z` | 후보 없음 | 그 프레임에서 **어떤 객체도** YOLO 후보를 얻지 못함 | 69 |
| `T` | 클래스 전환 | 직전 프레임과 수락 클래스 집합이 달라진 지점 (변화 큰 순 10/데이터셋) | 60 |
| `G` | 점수 근접 | 같은 물체를 두 클래스가 거의 같은 점수로 주장 (gap 작은 순 10/데이터셋) | 60 |
| `S` | 소형·가림 | 검출 박스가 가장 작거나 mask/bbox 비율이 가장 낮음 (6/기준/데이터셋) | 60 |

> **상한을 왜 걸었는가**: 상한 없이 `T`·`G` 를 전부 넣으면 **2,016 프레임(전체의 77.7%)**
> 이 뽑혀 "전수 라벨을 피한다" 는 목적이 무너집니다. 근거 수치는
> `ism_fusion_research/results/gt_frame_selection.csv` 에 있습니다.
> `U`(균등)와 `Z`(후보 0)는 각각 무편향 분모와 proposal miss 직접 증거라 상한을 걸지 않았습니다.

## 7. 이미지 보는 법

두 가지 방법 중 편한 쪽을 쓰시면 됩니다.

**(a) 개별 프레임** — CSV 의 `image_path` 를 그대로 열면 됩니다. 원본 해상도라 가장 정확합니다.

```
gt_input/frames/<dataset>/frame_<6자리>.png
```

**(b) contact sheet** — 9장씩 묶은 시트. 빠르게 훑을 때 씁니다.

```
gt_input/contact_sheets/<dataset>_sheet_<번호>.jpg
```

각 썸네일 위에 `dataset  f<frame_id>  [층코드]` 가 찍혀 있어 CSV 행과 바로 대응됩니다.
썸네일은 420 px 입니다. **작거나 흐려서 확신이 안 서면 반드시 (a) 원본을 여십시오** —
이전에 300 px 썸네일로 판정하려다 실패한 전례가 있어 무리하게 적는 것보다 `unsure` 가 낫습니다.

## 8. 다 채우신 뒤 자동으로 계산되는 것

`visible_objects` 만 있으면 아래는 **코드로 자동 산출**됩니다. 추가 입력이 필요 없습니다.

- 객체별 **visible positive frame** 수 (지금까지 없던 분모)
- 그 프레임에 해당 객체의 **YOLO 후보가 존재했는가**
- **proposal miss** = 보이는데 후보 없음 (단계별로 raw / conf·NMS / threshold / top_k 분해)
- **최종 FN** = 보이는데 최종 수락되지 않음
- 프레임별 **클래스 confusion** (보이지 않는데 수락된 객체 = FP 후보)
- 객체 크기·가림 수준별 recall (`S` 층 활용)

## 9. 이 GT 로도 확정할 수 없는 것

BBox 가 없으므로 다음은 **자동 확정이 불가능**합니다.

- 후보 BBox 와 실제 객체의 **정확한 IoU** (후보가 맞는 위치인지)
- **mask 정확도** (MobileSAM 분할 품질)
- 같은 프레임 안 **동일 클래스 다중 인스턴스** 구분 (우유 2개가 있는 경우 등)

이 항목이 필요한 프레임은 별도로 추려서 **후속 BBox 검수 목록**을 만듭니다
(`results/bbox_review_queue.csv`). 지금 단계에서는 하지 않으셔도 됩니다.
